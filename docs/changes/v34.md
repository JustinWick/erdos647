# v34 — disjoint core/research module roots

## PR readiness based on the uploaded v33 run

The standalone core's local acceptance gate passed: library, examples, expanded
types, and all 95 transitive-axiom reports. The v33 manifest/schema and cache
repairs reached real proof checks and no longer blocked setup.

The **combined fixes PR is on hold**: research audit imports failed, and this
revision repairs their module ownership. The release criterion for claiming the
repository-wide fixes complete is a current `all` run with every one of the 13
registered gates passing, including exact-type and axiom checks. A build alone,
a tooling-only run, or a core-only run does not satisfy that combined criterion.
The final asymptotic endpoint is not part of these implemented gates and is not
required to land a packaging-fixes PR.

A narrowly scoped core-only PR already has supporting local evidence. This is
not an assessment of a live GitHub branch, conflicts, approvals, or remote CI.
Existing workflow triggers are left untouched.

Suggested combined PR title once its gates pass:
**Fix Lake manifests and isolate research module imports from the finite core**

## Root cause

Lean picks the first directory owning a module's top-level component. The v33
research search path correctly included core before research, but both packages
owned `Erdos647Sieve`. Successful research builds therefore did not imply that
standalone Lean audit imports could find those objects. Changing search order
would only reverse which half of the shared root failed.

## Changes

- Move twelve research modules to `Erdos647Research.*`; preserve theorem names,
  statements, and proof bodies. Adjust only their import lines.
- Move the import-only upstream wrapper to `Erdos647Research.Compat.PNTPlus` so it
  cannot collide with upstream's `PrimeNumberTheoremAnd` root.
- Update research Lake roots, build targets, audit imports, and source guards.
  Axiom targets and expanded theorem statements are unchanged.
- Check compiled-module ownership after builds, before theorem audits.
- Retire exactly matching old source paths to provenance once when the overlay
  is applied in place. Preserve edits and refuse conflicts. Fresh checkouts with
  only the new paths skip this step; it is not a source synchronization system.
- Keep toolchain/dependency pins, core source/configuration, workflow edits,
  caches, and previous results unchanged. Diagnostic prefix: `erdos647_repo_v34_results_`.

Module-path policy follows Lean 4.32.2's `src/Lean/Util/Path.lean`, specifically
`SearchPath.findWithExt` and `findOLean`.

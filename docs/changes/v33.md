# v33 — repository manifest and resume repair

This update targets the standalone v32 repository layout. It is not a migration
overlay for the earlier nested research installation.

## Changes

- Preserve the two package identities and Lake configuration. Serialize their
  names as `«erdos647-sieve»` and `«erdos647-research»` in the lockfiles.
  The research lockfile's local core dependency uses the same escaped name.
- Check that each root manifest name matches the Lean identifier in its lakefile.
- Before dependency preparation, invoke the installed Lean/Lake manifest parser
  using `scripts/check_manifests.lean`. This catches invalid lockfiles before
  attempting repository fetches or Mathlib cache retrieval.
- If the pinned compiler and dependency checkouts are present but the compiled
  Mathlib cache is missing, resume only the cache retrieval. Existing caches
  remain untouched. Tool and Git checkout setup is still explicitly selected.
- Preserve per-package setup errors in both the JSON and human-readable reports.
- Record CI workflow YAML changes separately from local proof inputs. Changes to
  Lean sources, scripts, tests, manifests, or other checked inputs still invalidate
  the local run.
- Use uniquely named `erdos647_repo_v33_results_...zip` diagnostics.
- Keep the user's CI workflow file untouched; this archive does not contain it.

No mathematical proof file, exported declaration, numerical constant, audit
target, dependency revision, toolchain pin, or axiom allowlist changes. Both
top-level entry points and ordinary Lake commands remain the existing interfaces.
